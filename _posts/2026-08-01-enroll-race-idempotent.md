> Flown LMS에서 수강 최초 등록 경로의 동시성 버그를 CodeRabbit 리뷰로 잡고 수정한 기록.
> 관련 커밋: `d9268eef`

## 1. 문제 정의

한 사용자가 같은 강의를 **최초로 등록**하는 요청이 거의 동시에 두 번 들어올 수 있다(더블클릭·재시도). 불변식은 이렇다.

> **(member_id, course_id)의 수강 등록은 1건이어야 한다.**

이 불변식이 애플리케이션 조회(`있으면 스킵, 없으면 등록`)에만 있으면, 동시 요청에서 깨진다. (범위: 최초 등록의 동시성. 비범위: 등록 이후 수강 로직.)

## 2. 원인 — read-then-write 레이스

동일 사용자의 최초 등록 요청이 동시에 들어오면, **두 스레드 모두 조회 단계에서 "미등록"으로 통과**한다. 그리고 각자 INSERT를 시도한다. DB에는 `uk_enrollment_member_course` 유니크 제약이 있으므로 한쪽은 위반으로 실패하고, 그대로 두면 **500 에러**가 사용자에게 나간다.

즉 "조회 후 없으면 INSERT" 패턴은 단일 요청에선 맞지만 **동시성에선 취약**하다. (이 구조 자체는 영상 진도 중복행 버그와 같은 계열이다.)

이 문제는 운영에서 터지기 전에 **CodeRabbit 코드 리뷰(#2)에서 잠재 위험으로 지적**되어 선제 수정할 수 있었다.

## 3. 조치 — 위반을 "이미 등록됨"으로 변환

유니크 제약 위반을 에러로 터뜨리는 대신, **"먼저 들어온 요청이 이미 등록에 성공했다"는 의미로 해석**했다. `DataIntegrityViolationException`을 잡아 도메인 예외 `ENROLLMENT_ALREADY_EXISTS`로 매핑한다.

```java
try {
    // ... save(enrollment)
} catch (DataIntegrityViolationException e) {
    throw new BusinessException(ErrorCode.ENROLLMENT_ALREADY_EXISTS);
}
```

한 가지 전제가 이걸 가능하게 했다. PK가 `IDENTITY` 전략이라 `save` 시 INSERT가 **즉시 flush**된다. 그래서 제약 위반이 `try` 블록 안에서 바로 표면화되어 잡을 수 있다. (지연 flush면 트랜잭션 커밋 시점에 터져서 이 자리에서 못 잡는다.)

그리고 `ENROLLMENT_ALREADY_EXISTS`는 상위에서 **실패가 아니라 멱등 성공**으로 처리된다. 결과적으로 동시에 두 번 눌러도 등록은 한 번, 두 요청 모두 "등록됨" 상태를 본다.

## 4. 트레이드오프

- **근본 방어는 DB 유니크 제약**이다. 앱 레벨 "조회 후 INSERT"는 보조일 뿐, 동시성에선 제약이 최종 방어선이다.
- 예외를 성공으로 변환하는 것은 신중해야 한다. 여기서는 "이미 같은 등록이 존재"라는 게 사용자 의도와 일치하므로 멱등 성공이 맞다. 하지만 아무 `DataIntegrityViolationException`이나 성공으로 바꾸면 진짜 오류를 숨길 수 있어, **이 경로의 제약(수강 유니크)에 한정**해서만 변환했다.

## 5. 채용 관점에서 강조하고 싶은 점

이 수정은 운영 장애가 난 뒤가 아니라 코드 리뷰에서 잠재 위험을 받아들여 선제적으로 고친 사례다. 리뷰 지적을 방어적으로 넘기지 않고, 사용자 더블클릭·네트워크 재시도라는 실제 시나리오로 바꿔 생각한 점을 보여주고 싶었다.

기술적으로는 "예외를 성공으로 바꾸는" 위험한 선택을 아무 데나 적용하지 않았다는 점이 중요하다. 같은 `(member_id, course_id)` 등록이 이미 존재한다는 의미가 사용자 의도와 일치하는 경우에만 멱등 성공으로 해석했다.

## 6. 배운 것

- **"조회 후 없으면 생성"은 동시성에서 깨진다.** 유일성은 DB 제약으로 내리고, 위반을 어떻게 해석할지(에러 vs 멱등 성공)를 도메인 관점에서 정해야 한다.
- **flush 타이밍을 알아야 제약 위반을 잡는 위치가 정해진다.** IDENTITY의 즉시 flush 덕분에 `try`에서 잡을 수 있었다.
- **리뷰가 운영 장애를 미리 막는다.** 이 버그는 사용자 피해 전에 코드 리뷰에서 걸러졌다.
